# Lite-GD Reproduction Audit (2026-09-25)

Branch: `paper-aligned-repro-20260925`  
Original branch `main` is intentionally left unchanged.

## 1. Reproduction target

The target is the Lite-GD formulation described in:

- WWW 2024, *Lightweight GCN Encoder and Sequential Decoder for Multi-Candidate Carpooling Route Planning in Road Network*.
- TMC 2025, *A Lightweight Encoder-Decoder Framework for Multi-Candidate Carpooling Route Planning in Large-Scale Road Networks*.

The paper-level pipeline is:

1. node/edge input embedding;
2. joint node-edge GCN encoder;
3. binary/variance filters;
4. supervised node/edge pre-training from complete optimal routes;
5. distance + direction-angle domain feature crossover;
6. gating between domain features and road-edge representations;
7. sequential pointer decoder;
8. rule mask enforcing per-passenger pickup-before-dropoff and one selection per candidate set.

TMC reports an 8:1:1 train/validation/test split.

## 2. Current `main` is not a faithful runnable implementation

### 2.1 Documented entrypoint is broken

README asks users to run `python code/Lite-GD/train.py`.

A clean server preflight at commit `57e73e0f6c10c704b6a7ead24eeac4a5404909fb` found required runtime assets missing from current `main`:

- `sim_data/chengdu_data.npy`
- `sim_data/chengdu_directed_shortest_distance_matrix.npy`
- `sim_data/Data_Generator.py`
- `distance_matrix.pth`

The documented entrypoint fails at import time because `Data_Generator` is not present on the path used by `train.py`.

### 2.2 README training path is a Pointer Network, not the paper Lite-GD

`code/Lite-GD/train.py` imports `PointerNet` and never imports `MCRP_Net.py`.

The main training path therefore does not contain the paper's:

- node-edge GCN encoder,
- pre-training classification task,
- binary/variance filters,
- GCN-to-domain gating path.

### 2.3 `MCRP_Net.py` is an unfinished/dead experimental path

Observed issues include:

- hard-coded local absolute paths under `/Users/mali/` and `~/Documents/`;
- hard-coded `nn.Linear(5941, ...)`, binding it to one graph;
- repeated reuse/mutation of a shared DGL graph object across cases;
- case-edge feature assignment uses `edges_of_id.iloc[0, ...]` inside the per-edge loop;
- masking multiplies scores by zero rather than reliably using `-inf`;
- cross-entropy is applied to values already passed through softmax in parts of the path;
- it is not connected to the README training/evaluation entrypoint.

These issues mean success of the README path cannot be interpreted as success of the paper model.

## 4. Legacy checkpoint forensic result

The historical `param_5_1000_best.pkl` evaluated on the deleted 1,000-example tensor gives:

- exact output-sequence accuracy: 67.1%
- selected-point accuracy: 88.95%
- mean route gap: 1.17%
- median gap approximately 0
- 95th-percentile gap: 6.57%

These values are **not valid held-out reproduction evidence**.

Both legacy `train.py` and `val.py` load the same `sim_data/chengdu_data.npy`; no 8:1:1 split is implemented. The training code also loads an existing checkpoint before training. Therefore the attractive legacy numbers can be explained by train-set re-evaluation / leakage.

## 5. More important: legacy sequence semantics are narrower than the paper definition

The WWW/TMC problem definition requires only:

- route starts from the car;
- for each passenger, pickup precedes that passenger's drop-off;
- capacity constraint.

For two passengers, this gives 6 precedence-feasible task orders.

However, all 950 recovered two-passenger labels use only 4 task orders: exactly
`2! x 2!`, i.e. **all pickups are completed before any drop-off**.

For the 50 three-passenger cases, historical labels likewise put all three pickups before all three drop-offs. That is a subset of at most `3! x 3! = 36` orders, whereas per-passenger precedence permits 90 orders.

The legacy `PointerNet.py` contains the same restriction in its hard-coded mask:
early decoder steps permit only pickup slots and later steps permit only drop-off slots.

Thus the old model and labels are mutually consistent, but they solve a strictly narrower routing problem than the paper text specifies. This can change the true optimum, route gap, and exact accuracy.

## 6. Candidate-set semantics

Recovered order files store pickup candidate sets in the first half and drop-off sets in the second half, but passenger identity is permuted per case.

The paper type ids are:

- passenger i pickup: `2*(i-1)`;
- passenger i drop-off: `2*i-1`;
- car: `-1`.

The reproduction code recovers each case's candidate-set/passenger mapping by a one-to-one match between historical label type ids and selected edges. New mask logic must use this case-specific pairing instead of assuming a fixed slot-to-passenger mapping.

## 7. Trustworthy reproduction protocol

The new branch uses these rules:

1. never treat old checkpoint metrics as reproduction results;
2. use deterministic stratified 8:1:1 train/validation/test splits;
3. certify or regenerate optimal labels under the **paper precedence constraint**;
4. report mean gap, distributional gap statistics, exact route accuracy, and two-/three-passenger results separately;
5. first establish a clean decoder baseline with:
   - spherical-distance features,
   - direction-angle features,
   - feature crossover,
   - gating,
   - rule-based mask;
6. then add the node-edge GCN and route-based pre-training;
7. finally test the filter separately, because the paper's own ablation shows the filter mainly affects efficiency and has a smaller quality effect than feature crossover or pre-training.
